# Dotfiles

Chezmoi, two repos: public (`~/.dotfiles`) + private (`~/.dotfiles-private`), split by audit surface. Bootstrap: `install.sh`. This half: shell / tmux / ghostty / nvim / OMP and cross-tool integration. Agent rigs, secrets, personal tooling: private half — [`~/.dotfiles-private/CLAUDE.md`](~/.dotfiles-private/CLAUDE.md). This repo's `.chezmoiignore` excludes `.claude` and `CLAUDE.md`, so the private half is sole source of truth for agent config.

## Rules (non-obvious, not derivable from code)

- **Source-first re-add loop** — edit source → `home apply` → validate runtime with the tool's own validator → `home re-add`. Runtime is never the source of truth. Operational form injected per-edit by `~/.claude/rules/10-chezmoi.md`.
- **`RUNTIME_KEYS` is empty by design** — nothing is harvested live→source; an unmirrored `/model` or `/config` change is wiped on next apply. `PRIV_RUNTIME_OWNED` force-applies `~/.claude/settings.json` + `~/.pi/agent/settings.json`. Mechanism: [`~/.dotfiles-private/ARCHI.md`](~/.dotfiles-private/ARCHI.md) "Deploy loop".
- **chezmoi never prunes** — a deleted source file leaves its deployed target; `rm` it manually after `apply` or it becomes an unflagged orphan.
- **`.chezmoiignore` patterns must never start with `/`** — chezmoi 2.72.0 rejects a leading slash (`chezmoi: .chezmoiignore:6: /ARCHI.md: invalid path`) and then *every* chezmoi command exits 1, freezing the whole rig until it is fixed. A bare `ARCHI.md` is already root-anchored, since patterns match the target path relative to `~`. Shipped in `23f88bd`, latent until Homebrew bumped chezmoi.
- **Keybind descriptions live as tmux `-N` notes, never in a second file** — `dot_bin/executable_keys` (`keys`) generates the whole cheatsheet at run time from each tool's own reporting: `aerospace config --get mode.<m>.binding --json`, `ghostty +list-keybinds`, `tmux list-keys [-N]`, `zsh -i -c bindkey`, `nvim --headless` + `nvim_get_keymap`. A new binding worth remembering gets `-N "Label"` on the `bind` line itself; nothing else to update. This replaced `keyb.yml`, a hand-maintained copy that drifted four times in eight commits (`7196759`, `52a2f10`, `0bc129e`, `920bb22`) and still claimed `C-t` was transpose-chars long after fzf took it. Two tmux quirks the parser handles: `list-keys -N` prints the prefix key ahead of **every** row including the prefix-free root table, and keys appear both double-quoted (`"M-;"`) and backslash-escaped (`\#`) in the same table.
- **The workspace list lives in THREE files** — `dot_config/sketchybar/lua/items/spaces.lua`, `dot_config/sketchybar/executable_sketchybarrc` (`left_island` bracket), `dot_config/aerospace/aerospace.toml` (`persistent-workspaces`). Fewer than all three renders but falls outside the island, no error (drifted once — `1e2658e`). Do not DRY it away; update all three.
- **WS4's 2/3 : 1/3 split is a script, because AeroSpace resizes in pixels only** — `aerospace resize` takes `width|height|smart|smart-opposite` and a pixel count (0.21.3-Beta), so a ratio has to be computed. `dot_config/aerospace/scripts/executable_ws4-split.sh` is wired to the WS4 `on-window-detected` rule; the rule-triggered path is `unverified` — the script has only been observed run by hand, because verifying the rule needs a freshly opened Spark or Spotify window. It sets `layout --workspace 4 --root h_tiles`, sends Spark one slot left with `move left --boundaries workspace --boundaries-action stop` (leftmost only because the script refuses to run unless WS4 holds exactly two windows), and gives Spotify `usable / 3`. **It must call `aerospace` by absolute path.** AeroSpace.app runs with `PATH=/usr/bin:/bin:/usr/sbin:/sbin`, so a bare `aerospace` is `command not found` (127) in every rule-triggered run, and the script's own `2> /dev/null` turns that into a silent no-op — the split simply never happens and nothing reports it. `place-window.sh:4` pins the same path for the same reason. Probed by running the script under `env -i PATH=/usr/bin:/bin:/usr/sbin:/sbin`: it reaches `resize width 841 --window-id 48`. The window lookup retries 20 times at 50 ms, like `place-window.sh:29-40`, because a window AeroSpace has just detected may not be in its model yet. `usable` is the screen width less `outer.left`, `outer.right` and one `inner.horizontal`, and the three gaps are read out of `aerospace config --config-path` with `sed`, never hardcoded. The width is `NSScreen.visibleFrame` keyed by AeroSpace's own `%{monitor-appkit-nsscreen-screens-id}`, exactly as `place-window.sh` does it — **not** Finder's `bounds of window of desktop`, which returns the full frame (a side Dock then overstates `usable`) and needs a separate Automation→Finder TCC grant.
- **WS5 is messengers in `h_accordion`, WS4 is Spark + Spotify only, and Claude Desktop has no rule at all** — the Claude rule was deleted, so the catch-all floats it on whichever workspace is focused when it opens (probed: it opened floating on the focused WS2). Fantastical falls to the same catch-all, and the Steam rule is gone — WS5 is no longer gaming, and Steam is installed, so a game now opens floating and centred on whatever workspace has focus instead of parking on 5. That is the operator's call, made on 2026-08-20. Beeper and Fantastical are both absent from this machine, so their clauses are inert until installed.
- **tmux mouse selection is pane-aware** — drag copies via OSC 52; Shift+drag falls back to native Ghostty selection.
- **tmux names Shift-Tab `BTab`** (`M-BTab`, not `M-S-Tab`).
- **Dual keybindings for Alt+Shift combos** — bind both `M-S-D` (CSI u) and `M-D` (legacy). Ghostty 1.3.0+ (#9406) strips Shift from Option-modified keys in modifyOtherKeys mode; `extkeys` is deliberately omitted from `terminal-features` to stay in legacy mode where case survives. Details in keybinds.conf/tmux.conf comments.
- **zsh's `Ctrl+Shift+W/E/A/S` are Ghostty rewrites arbitrated by tmux, not zsh keys** — in legacy encoding no terminal can tell `Ctrl+Shift+X` from `Ctrl+X` (one control byte either way), so `config.ghostty` maps each to `text:\x1b\x<byte>`; tmux receives `M-C-x` and splits it on `@pane-is-vim` exactly like `M-H/J/K/L` — vim panes get plain `Ctrl+X` back, every other pane gets `M-C-x`, which `.zshrc` binds as `^[^X`. The vim branch exists so vim panes keep native `Ctrl+X` semantics rather than a stray `<Esc>` prefix; it is **mode-scoped, not blanket protection** — probed on a throwaway socket with buffer `5 foo`: in insert mode the branch turns `<Esc><C-a>` (increments to `6 foo`) into `i_CTRL-A` (`5 foo5 foo`), but in normal mode both paths increment identically, because plain `C-a` increments too. Three residual holes, accepted: `Ctrl+Shift+A` still increments in neovim normal mode (only an nvim-side remap could stop that); outside tmux (quick terminal, bare Ghostty) there is no arbitration; and `beginning-of-line`/`end-of-line` exist only under Ghostty, since `^A`/`^E` are reassigned and Home/End are unbound in this rig.
- **Forward zsh motions bind the `.`-prefixed builtin widgets** — `bindkey '^S' .end-of-line`, `'^[^S' .forward-word` (plain is the line, `+Shift` is the word). zsh-autosuggestions' `_zsh_autosuggest_bind_widgets` lists `.*` in its `ignore_widgets`, so the dot form moves the cursor without swallowing the suggestion; the undotted names are in its PARTIAL_ACCEPT / ACCEPT lists and are used deliberately on `Ctrl+E` / `Ctrl+Shift+E`. Backward motions need no guard — nothing accepts leftwards, and `_zsh_autosuggest_modify` restores POSTDISPLAY when the buffer is unchanged.
- **`DIRENV_LOG_FORMAT=""` silences direnv's status lines but KEEPS its errors** — set in `.zshrc` above the hook, it drops `direnv: loading …`, `export +VAR` and `unloading` from every prompt in a directory with an `.envrc`. Errors do not use that format and still print: a blocked `.envrc` still says `direnv: error … is blocked` and a failing `.envrc` still prints the shell error (probed both, direnv 2.37.1). It must be exported, since the direnv binary reads it on each hook run.
- **`Ctrl+R` is atuin, not fzf** — atuin runs `--disable-up-arrow`.
- **Emacs mode default** (`bindkey -e`), `C-z` toggles vi — required for lag-free Alt binds.
- **Popup scripts live in `dot_config/tmux/scripts/`**, not `dot_bin/` — tmux-only helpers, that is. `keys` and `mdr` are the exceptions and belong in `dot_bin/` precisely because they must run standalone outside tmux; the `M-?` popup is only a frame around `keys`, never a second implementation, and `mdr` is reached from a bare shell by `Ctrl+F`.
- **There is ONE reader, `dot_bin/executable_mdr`, and the tmux popup is only a frame around it** — `M-f` runs `display-popup … "MDR_HEIGHT=100% ~/.bin/mdr"`. `dot_config/tmux/scripts/executable_read-popup.sh` was the second implementation and is deleted; its deployed copy was removed by hand, because chezmoi never prunes. Four switcher-style tabs reload the list in place: All (`Ctrl+A`, default, markdown plus `.scratchpad`), Docs (`Ctrl+D`, markdown only), Scratch (`Ctrl+S`, every file under `.scratchpad/` and `.claude/`, ignore rules OFF), Files (`Ctrl+F`, every file, `.gitignore` respected). The same names are CLI arguments — `mdr docs`, `mdr scratch ~/dev/x` — so the popup passes no view at all and starts on All. `MDR_HEIGHT` exists because the two callers want different heights: 80% keeps scrollback visible in a bare shell, and a popup needs 100% or fzf draws in the top 80% of it with dead space below. `dot_config/zsh/fzf.zsh:40` exports `--height=60%` inside `FZF_DEFAULT_OPTS`, which BOTH callers inherit, so the value is always stated. **Row rendering is `perl`, never a bash `while read` loop.** The loop cost 17.1 s on the 148k-row Files view from `$HOME`; the same rows through `perl -0 -ne` take 0.49 s (probed). All four views are now under 0.5 s from `$HOME`: All 6.6k, Docs 6.5k, Scratch 16.4k, Files 148k. Rows are NUL-delimited `<display><TAB><path>` with the path **last**, and every tab and newline in the display half is replaced, so the first tab in a row is always the separator that `--preview` and the pager cut on. The display is the full relative path, dim directory plus bright basename, never a padded name column: fzf matches the `--with-nth` text only, so a padded column silently broke path-ordered queries. **A positive `--glob` is a whitelist, so a view that lists non-markdown must carry no markdown glob at all** — `--glob '.scratchpad'` alone returned ZERO rows for Files, because the directory matched the whitelist and nothing inside it did. Files therefore runs the bare walk, and `.scratchpad` reaches it through the Scratch tab instead. Scratch discovers its roots with `find -maxdepth 4` and walks them with `--no-ignore`, because `~/.config/git/ignore:35` and `:53` ignore both directories outright. The renderer flags are restated on purpose: `~/.config/bat/config` is tuned for non-interactive use (`--paging=never`, `--style=changes`, `--pager=delta`), so the reader passes its own paging, style and pager — `less -R`, since delta decorates diffs, not plain files. Both tools drop colour when stdout is not a tty, which is exactly an fzf preview pane, so previews force `--color=always` / `-s <style>`. And `glow` renders plain text off a tty **even with `style:` set in `glow.yml`** — the config key works on a tty only (probed via `script -q /dev/null glow`), so the `-s` flag on the command line is what colours the preview. The Catppuccin palette and the fzf colour string are copied into `mdr` rather than sourced from `dot_config/tmux/scripts/colors.sh`: the reader must run with no tmux on disk.
- **`display-popup` inherits `FZF_DEFAULT_OPTS`, so every fzf inside one must state the options it depends on** — the tmux server environment carries the whole block from `dot_config/zsh/fzf.zsh:40` (`tmux show-environment -g | grep FZF`), `--height=60%` and `--keep-right` included, and an inherited option is invisible at the call site. `--height=60%` is the loud one: fzf draws in the top 60% of the popup with dead space below. Command-line options beat `FZF_DEFAULT_OPTS`, so `mdr` states its height (`MDR_HEIGHT`) and `--keep-right` outright — it wants keep-right, because it displays whole paths and an overflowing row must lose leading directories, never its filename. The negation `--no-keep-right` also works if a popup wants the other truncation; it is absent from `fzf --help` but accepted (probed on 0.74.3). `--keep-right` also truncates `--header` and `--footer` from the left, and both span the LIST column — 40% of a popup that is itself 80% of the terminal, so ~31 columns on a 100-column terminal. Shortening the labels to `^D Docs · ^F Files · ^S Scratch` was not enough; measure at the popup's real interior width, not in a bare pane, or the check passes while `^D Docs` still vanishes. The reader therefore carries its tab bar on the **outer border label** (`--border-label` + `change-border-label`), which spans the whole fzf frame and renders complete down to a 62-column interior (probed at 62/78/126). ANSI survives in a label, so the active tab keeps its accent. The footer stays in the list column and is the sacrificial one. `switcher.sh` escapes `--height` for a different reason: it uses fzf's own `--tmux center,55%,60%` popup mode (`:461`), which sizes the window itself; it inherits `--keep-right` unstated, so its padded name column left-truncates on a narrow popup.
- **The switcher's bookmark store is runtime state at `~/.local/state/switcher/bookmarks`, and chezmoi must never manage that path** — `Ctrl+S` in the `M-o` switcher toggles the highlighted row's directory in that file, so the UI writes it. A chezmoi-managed copy would be overwritten by the next `home apply`, exactly as **`RUNTIME_KEYS` is empty by design** describes; that is why the store sits under `XDG_STATE_HOME` and not beside `projects.json`. The format is one absolute path per line, so the toggle is `grep -vxF` and needs no `jq`. The declarative half stays separate and stays optional: `~/.config/switcher/projects.json` holds `configDirs[]` (plain strings, feeds the **Config** category), `baseFolders[]` (`{scope, path}` — every depth-1 child of `path` becomes a project; `scope` is read into `_scope` and discarded, so it does nothing) and `favorites[]` (`{rootPath, enabled}`). Before bookmarks existed the Projects tab returned nothing at all without that file. It now lists bookmarks first, then favorites, then scanned base folders, deduplicated by path, and it works with no `projects.json` on disk. Every `fd` call site strips a trailing `/`, and so do the bookmark and `favorites` loops, because `fd` appends one to a directory while `toggle_bookmark` stores the stripped form, and the merge in `_source_all_raw` deduplicates on the literal path string; the zoxide and `configDirs` sources need no strip, since neither emits one. Bookmarked rows carry a `nf-md-bookmark` glyph in every tab except Grep, and the toggle ignores a row that is not a directory. **`Ctrl+S` binds `transform(...)`, never `execute-silent(...)+reload(...)`** — the chained form fires the reload unconditionally, and a Grep row is always a file and therefore always a no-op, so one keypress rebuilt the whole Grep list for nothing: the per-line `sed|cut|cut` loop costs about 15k forks and ran 54 s from `~/.dotfiles` (probed). Under `transform`, `--bookmark` prints `reload(<self> --source-current)` only when it actually wrote to the store and prints nothing otherwise, so a no-op keypress is free in every tab. **That reload must replay the active tab, not `all`** — `do_source` records `<source> <arg>` into the per-invocation tmpfile named by `$SWITCHER_TAB_FILE`, and `--source-current` reads it back; fzf runs the command through the shell and inherits the exported variable. `Ctrl+S` is NOT free in the rig at large — `dot_config/zsh/dot_zshrc:68` binds `^S` to `.end-of-line` — but fzf owns the key inside its own popup, so the switcher has no conflict; `config.ghostty` binds only `ctrl+shift+s`, and tmux binds `M-s` and `M-C-s`, never `C-s`. **`is_bookmarked` must guard `-n "$1"`** — with no store on disk `_BM_SET` is exactly `$'\n\n'`, so an unguarded match returns true for an empty path, and the tmux rows, the one source never filtered by `-d`, then starred a window whose `#{pane_current_path}` was empty on a machine with nothing bookmarked at all.
- **`mdr`'s walk is capped only off-repo, and the gate reads the CURRENT DIRECTORY** — rg applies ignore rules only inside a repository, so off-repo the whole of `$HOME` is fair game; uncapped it emitted 83k rows in 33 s at 640% CPU, on one keypress. `git rev-parse --is-inside-work-tree` therefore gates `--max-depth 6 --glob '!/Library' --glob '!/.Trash' --glob '!/.cache'`. Because the gate reads the cwd, the walk must be the cwd too: `mdr` takes at most one directory and `cd`s into it rather than passing it to rg. Passing a path while the shell sat in a repo skipped the cap entirely, and the three `/`-anchored excludes go inert against any explicit path argument (both probed). **The cap loses files and says nothing**: from an off-repo root, anything deeper than 6 path components is unreachable. `.scratchpad` is re-included in the All view with a bare `--glob '.scratchpad'`, NOT a second `--no-ignore` pass: the ignore file ignores the DIRECTORY, so rg prunes it before descending and no markdown glob can reach inside. A whitelist glob on the directory name stops the pruning; the files below are then judged on their own paths, which no ignore rule matches. The glob carries no `/`, so it matches the basename at any depth (probed: `repo/.scratchpad/deep/b.md` from the parent). `--glob '.scratchpad/**'` does NOT work — it never matches the directory entry, so the prune still happens. `.claude` is excluded from All, Docs and Files **by an explicit `--glob '!.claude'`**, never by gitignore: `~/.config/git/ignore:35` holds off-repo, where it is precisely `~/.claude` that would swamp the list (1,498 markdown files, probed). The Scratch tab is where it is read. Inside a repo the ignore file only prunes DIRECTORIES here — a positive `--glob` whitelists a file over gitignore, which is why `CLAUDE.md` and `AGENTS.md` are listed despite `~/.config/git/ignore:38,42`. `Ctrl+F` in zsh opens it (widget: `zle -I` → `mdr` → `zle reset-prompt`). That key was `forward-char`, which zsh-autosuggestions lists in `ZSH_AUTOSUGGEST_ACCEPT_WIDGETS` (`zsh-autosuggestions.zsh:74`), so the bind takes away one way to accept a whole suggestion — `Ctrl+E` (`end-of-line`) is in the same list and still does it. The selection is read as one NUL record from a temp file, and the temp file is removed explicitly after the read, since the final `exec glow` never runs the EXIT trap.
- **`dot_config/glow/glow.yml` is a chezmoi template for one reason** — glow does not expand `~` in its `style:` key, so the Catppuccin Mocha style needs an absolute path: `{{ .chezmoi.homeDir }}/.config/glow/mocha.json`. The two failure modes differ and only one is loud: an unexpanded `~` path degrades quietly to unstyled output (exit 0), while an **absolute** path that does not exist kills every glow call on the machine — `Error: specified style does not exist`, exit 1, no output. `mdr` falls back to the built-in `dark` when the file is unreadable. `mocha.json` is a glamour `StyleConfig`, structured after `charmbracelet/glamour` `styles/dark.json`. Its 31-key `chroma` block stays hand-written: glamour has no `code_block.theme` escape hatch, and unknown `StyleConfig` keys are dropped in silence, so `"theme": "catppuccin-mocha"` renders byte-identical to no theme at all and to `"monokai"` (probed by `cmp`). Chroma quantises the hexes to the xterm-256 cube, so code-block colours are near, not exact. glow ships no catppuccin built-in — `-s catppuccin` and `-s catppuccin-mocha` both fail with `specified style does not exist`, while `ascii`, `auto`, `dark`, `dracula`, `light`, `notty`, `pink` and `tokyo-night` resolve (probed by name; not an exhaustive enumeration of glow's built-ins).
- **zsh config lives in `$ZDOTDIR` (`~/.config/zsh/`)** — `~/.zshenv` is a 2-line stub; with `ZDOTDIR` set there, `$ZDOTDIR/.zshenv` is never auto-read, so the stub sources it explicitly. Probe: `ARCHI.md` §3.
- **PATH lives in `path.zsh`, called from BOTH `.zshenv` and `.zprofile`** — macOS `path_helper` (via `/etc/zprofile`) hoists `/etc/paths` and only `.zprofile` runs after it. **Never verify PATH with `zsh -i -c` alone** — non-login, `path_helper` never fires. Test `-l -i`, `-i`, and bare. Full story: `ARCHI.md` §3.
- **`path.zsh` prepends fnm's *default alias* dir** (`~/.local/share/fnm/aliases/default/bin` — static symlink, no `fnm env` spawn) and it must sit **above `$HOMEBREW_PREFIX/bin`**. `_mrgsh_path_prepend` prepends each arg in turn, so the LAST argument lands FIRST in PATH. Without this, non-interactive zsh resolved Homebrew's node (transitive dep, two majors ahead) and fresh non-descendant shells (cron, LaunchAgent, GUI) lost `wrangler`/`cavemem`/`pnpm`. Interactive shells still get per-shell semantics from `.zshrc`'s later `fnm env`. Verify all four: `zsh -c`, `-i -c`, `-l -i -c`, `env -i … zsh -c`. **`dot_bashrc` carries the same prepend and must stay in sync** (it shipped the identical bug). The four root-owned `/usr/local/bin` symlinks into `fnm/aliases/default` are unmanaged machine state, not created by `install.sh`; they matter only for GUI/LaunchAgent processes reading no rc.
- **zsh startup is intentionally synchronous** — no plugin manager, no defer, no eval caching; plain clones in `$XDG_DATA_HOME/zsh/plugins` (update: `zsh-plugin-update`), direct `eval "$(tool init zsh)"`. Measured median 123ms (n=15, 2026-08-01). Do not re-introduce zinit/zsh-defer/eval caches. Budget + profile: `ARCHI.md` §4.
- **Static completions live in `~/.zfunc`** — generated by `update-completions` (run after upgrading gh/op/wrangler); never eval'd at startup.
- **OMP never reaps its per-session cache files** — `.zshrc` keeps the newest 50, glob `*.*-*-*-*-*.omp.cache` (UUID infix load-bearing). Two constraints, each shipped broken once:
  - The glob **must never match `init.*.zsh` or bare `omp.cache`** — `init.<hash>.zsh` is one stable-named file shared by every live shell with mtime never refreshed, so any mtime-sorted keep-N reaps it first — symptom `precmd:source: no such file or directory` on every prompt in every pane (`40c2f4b`). Reproduce: burst >50 shells, check the doomed slice for `init.*.zsh`.
  - The slice **must** be `"${(@)_c[51,-1]}"` — the unparenthesised form joins to one word and deletes nothing (shipped broken, grew 8.5k files).
- **Ghostty `shell-integration-features` is ADDITIVE over defaults** — source `cursor,sudo`; effective `cursor,sudo,title,no-ssh-env,no-ssh-terminfo,path` (only non-default delta: `no-sudo`→`sudo`). Verify with `ghostty +show-config`, never the source line. **Never set `no-path`** — it strips Ghostty's app dir from PATH and the `ghostty` command vanishes.
- **`set -g detach-on-destroy off`** — park/unpark UX; client stays attached when the current session dies.
- **Session persistence is intentionally manual** — `park-session.sh`/`unpark-session.sh`, no auto-restore. `save-session.sh` + `session-lib.sh` deleted in `4f12a1f` (write-only) — do not re-add.
- **Switcher/menu use `#{session_id}`, not `#{session_name}`** — names can carry quotes that break `display-menu` escaping; numeric `$N` IDs are quote-safe.
- **nvim is LazyVim plus a thin override layer** — `lua/config/*.lua` carries only deltas from LazyVim's defaults, `lua/plugins/` only what LazyVim does not ship. Check `~/.local/share/nvim/lazy/LazyVim/lua/lazyvim/config/` before adding an override; it already sets most of it. Delta table and rationale: `dot_config/nvim/README.md`.
- **The colorscheme is `catppuccin-mocha`, never bare `catppuccin`** — Neovim 0.12 ships `$VIMRUNTIME/colors/catppuccin.vim`, and the bare name resolves to that builtin, which ignores the plugin's `opts`; `transparent_background` then silently does nothing and Normal keeps `guibg=#1e1e2e`. Probe with `verbose highlight Normal` — it names the file that last set it.
- **`smart-splits.nvim` is what sets tmux's `@pane-is-vim`** (`smart-splits/mux/tmux.lua:160`, cleared at `:181`) — nothing under `dot_config/tmux/` sets it, everything there only reads it. Drop the plugin and both break silently, but differently: `M-H/J/K/L` falls through to `select-pane` (tmux panes only, never nvim splits — `keybinds.conf:46-53`), while `Ctrl+Shift W/E/A/S` sends the vim pane `M-C-w/e/a/s`, the zsh sequence nvim does not bind (`:63-66`).
- **lazy.nvim's update checker is off by preference** — no background git fetches, no nags. The checker itself never touches `lazy-lock.json` (`lazy/manage/init.lua:147-163`: `check` runs fetch/status/log, no `git.checkout`); only install, update and clean write it. Since the lock is chezmoi-tracked, update deliberately — `:Lazy update` then `home re-add`. Never `:Lazy sync`, which uninstalls anything absent from the current spec.
- **herdr is a peer multiplexer, not a tmux replacement — and its two config-loading failures are asymmetric** (`~/.config/herdr/config.toml`, public repo, adopted 2026-08-25). A bad **enum VALUE** silently discards the ENTIRE file and falls back to built-in defaults: `tab_bar_right = [{type="bogus"}]` returns `config parse error … unknown variant 'bogus' … ; using defaults`, not one disabled entry. A bad **key NAME** is merely ignored (`unknown config key …; ignoring key`), and a bad **key STRING** disables only that binding (`invalid keybinding: keys.next_tab = "alt+grave"; disabling binding` — the token is `backtick`, never `grave`). So a typo in a value is catastrophic and a typo in a name is free. `herdr config check` exits 1 on all three and 0 only on `config: ok`, which is why `_check_herdr` in `dot_bin/executable_home` gates on the EXIT STATUS and not on the stdout text.
- **`ctrl+alt` is unusable for herdr on this machine, even though herdr's own docs recommend it.** `keyboard.mdx` calls that band the safe prefix-free family; Aerospace owns almost all of it (`dot_config/aerospace/aerospace.toml:41-103` — `h j k l 1..5 tab enter f c r minus equal slash comma semicolon`, the arrows, and the `ctrl-alt-shift` variants) and intercepts above Ghostty, so herdr never sees those keys. The prefix-free band is `alt+`, which works because `config.ghostty:77` sets `macos-option-as-alt = left`.
- **The herdr ALT BAND binds only chords tmux already claims; that rule does not cover the prefix.** Any chord tmux already steals is free to reuse with no new loss, and any chord it does not is a live zsh binding — `alt+x` (`execute-named-cmd`) and `alt+b` (`backward-word`) were rejected on exactly that test. **The rule was shipped violated three times and an adversarial review caught all three**: `prefix = "ctrl+b"` (tmux's prefix is `C-Space`, so ctrl+b was stealing zsh `^B`, neovim `<C-b>` page-up and `less` page-back), `ctrl+h/j/k/l` for navigation (tmux binds `M-H/J/K/L` and never the ctrl forms, so it was stealing backward-delete, accept-line, kill-line and clear-screen — and fzf's own `ctrl+j` inside `mdr` and the switcher), and `alt+f` for the follow popup. All three are fixed: prefix is `ctrl+space`, navigation is `alt+shift+h/j/k/l`, follow is `prefix+f`. Multi-binding arrays work for both `[keys]` actions and `[[keys.command]] key`, validated per member, so every action keeps its prefix default beside its Alt chord.
- **`alt+f` is NOT free, for the reason `keybinds.conf:165-166` already records** — Ghostty ships `alt+arrow_right=esc:f` (confirmed in `ghostty +list-keybinds`), so Alt+Right arrives as `alt+f`. tmux put its reader on `M-i` for exactly this reason. A herdr binding on `alt+f` therefore fires on Alt+Right and also takes zsh's `^[f` (`forward-word`).
- **`ctrl+shift+h/j/k/l` can never reach herdr** — `config.ghostty:96-99` binds all four to Ghostty's own scrollback actions, and Ghostty consumes them. herdr's `config check` still reports `config: ok` for such a binding, because validating a chord's SYNTAX says nothing about whether the chord can arrive. A silently dead binding is the result. The separate `ctrl+shift+w/e/a/s` rewrites at `config.ghostty:90-93` do reach the pane, but herdr has no `@pane-is-vim` equivalent for them, so a neovim pane under herdr receives `<Esc><C-w>` and drops out of insert mode — a real regression against tmux, accepted for now.
- **herdr parses BOTH key encodings, so encoding mode cannot break a chord** — probed on a throwaway session: legacy ESC-prefix (`\ed`) and kitty CSI u (`ESC [ 100 ; 3 u`) both fire `split_vertical`. herdr pushes the kitty keyboard protocol at startup (`CSI > 7 u` in its output), so Ghostty will use kitty encoding; the legacy path works anyway. This is the opposite of the tmux situation, where `extkeys` is deliberately omitted and dual bindings are mandatory.
- **A `tab_bar_right` command entry renders PLAIN TEXT ONLY, and ANSI corrupts the row** — probed 2026-08-25: herdr strips the ESC byte and prints the rest of the sequence as visible glyphs, so `\033[38;2;243;139;168mPINK\033[0m` displayed as the literal text `[38;2;243;139;168mPINK[0m`. herdr then applies its own dim style to the whole entry. There is no way to colour a status entry, and the three-zone `status-format[0]` design in `theme.conf` is therefore unportable — herdr owns its tab row and exposes only right-aligned entries of five fixed types (`zoom`, `hostname`, `datetime`, `text`, `command`).
- **herdr refuses to start nested, and the check reads `HERDR_ENV`** — testing a scratch config needs `env -u HERDR_ENV -u HERDR_PANE_ID -u HERDR_TAB_ID -u HERDR_WORKSPACE_ID -u HERDR_SOCKET_PATH -u HERDR_BIN_PATH`, not `experimental.allow_nested = true`. herdr honours `XDG_CONFIG_HOME`, so a probe rig is `XDG_CONFIG_HOME=/tmp/x herdr --session probe` driven through tmux on a throwaway `-L` socket, with every assertion read back through `HERDR_SOCKET_PATH=<session>/herdr.sock herdr pane list`. **Never redirect the client's stdout to a file while probing** — the TUI renders to stdout, so `tmux capture-pane` then returns nothing and the screen looks blank while the session is perfectly healthy.
- **herdr WRITES its own `config.toml`, and that blocks every later `chezmoi apply` of the file** — the settings UI and the server both persist keys there (observed: `[ui.sound] enabled = true` appearing live-only). chezmoi then refuses with `has changed since chezmoi last wrote it` and tries to open a TTY, which fails outright in a headless session. `--force` is blocked by a rig hook, and deleting the target does not help, because the guard compares chezmoi's recorded hash. The surgical fix is `chezmoi --source ~/.dotfiles state delete --bucket=entryState --key="$HOME/.config/herdr/config.toml"`, then apply normally. Inspect first with `chezmoi state get --bucket=entryState --key=<target>` against `shasum -a 256` of the live file.
- **`home apply` validates the herdr SOURCE before deploying it** — `_check_herdr_source` renders the source into a throwaway `XDG_CONFIG_HOME` and runs `herdr config check` there, so a bad enum value cannot reach the live path at all. `home check` additionally verifies that every `plugin_action` id in the deployed config resolves in `herdr plugin action list`, because `herdr config check` returns `config: ok` for an action no installed plugin provides — the exact fresh-machine failure where bindings point at plugins that were never installed. `cmd_check` now returns non-zero when either fails.
- **Adopt `config.toml` and nothing else from `~/.config/herdr/`** — the directory also holds `herdr.sock`, `herdr-client.sock`, two logs, `session.json` and `.plugins.lock`, all live runtime state. The source dir must stay plain `dot_config/herdr/`, never `exact_`, or every `apply` would delete the sockets. `session.json` in particular holds the operator's dragged sidebar width and workspace tree; managing it would fight the UI on every apply.
- **Pane navigation is a RIG script, deliberately not the upstream herdr plugin** — `dot_config/herdr/scripts/executable_navigate.sh` on `alt+shift+h/j/k/l`, the same chords tmux uses. It asks `herdr pane process-info` whether the foreground process matches `^g?(view|l?n?vim?x?)(diff)?$`, then either forwards the chord with `pane send-keys` or moves focus with `pane focus`, falling back to forwarding when there is no neighbour. That is the `@pane-is-vim` arbitration, herdr-side. **`smart-splits.nvim` does ship its own `herdr-plugin.toml`, and it was tried first and then unlinked**, for two reasons: `herdr-navigate.sh:26-31` HARDCODES the forwarded key to `ctrl+h/j/k/l`, so the plugin cannot be moved off keys tmux never claimed; and `herdr plugin link` points into lazy.nvim's runtime directory, which chezmoi does not manage, so a fresh machine silently has no navigation. The rig script needs neither. neovim keeps its original `<A-H/J/K/L>` maps and needs no `vim.g` override — `smart-splits/config.lua:99-108` checks `are_we_herdr()` before `TERM_PROGRAM == "tmux"`, so each host self-selects (probed: `mux=herdr` inside a herdr pane). `jq` is required by the script.
- **herdr plugins are NOT chezmoi-tracked, so the reproduction path is the install commands, not the artefacts** — `~/.config/herdr/plugins/` holds fetched release binaries and a per-plugin config dir. Three are installed: `smart-splits.nvim` linked from lazy.nvim's runtime dir, plus `herdr plugin install persiyanov/herdr-reviewr --ref v0.36.0` (diff review beside the agent, `prefix+alt+r`) and `herdr plugin install smarzban/herdr-file-viewer --ref v1.16.0` (git-aware file explorer, `prefix+alt+e`). **Always pin `--ref`.** Both install scripts fetch a release archive and verify a SHA-256 sidecar shipped from that same release, which proves transport integrity and not provenance; herdr states plainly that it neither reviews nor sandboxes plugin code, and a plugin runs as you with your whole environment. `alexarthurs/herdr-sidebar` is deliberately absent — it duplicates file-viewer, and two file explorers is the bloat this rig refuses. **reviewr auto-runs unless told not to**: its manifest carries `events = [{on = "worktree.created"}]` and its own default is `auto_open = true`, so every worktree creation would launch the downloaded binary, which shells out to `gh`/`glab` for forge credentials. `~/.config/herdr/plugins/config/persiyanov.reviewr/config.toml` sets `auto_open = false`; that directory is plugin state, not chezmoi-managed, so it must be recreated by hand on a new machine. reviewr also plants `~/.local/bin/herdr-reviewr` as a symlink into its plugin directory, and `~/.local/bin` sits ahead of Homebrew on `PATH`. The `herdr-plugin` GitHub topic held 824 repositories on 2026-08-25 and is an unreviewed self-tagged index; the adoption bar used here was several contributors, a versioned release, activity within the week, a license, and a readable surface.
- **New herdr capability goes on a PREFIX chord, parity goes on the Alt band** — the Alt band is nearly exhausted by the tmux-parity keymap, and the bind-only-what-tmux-claims rule leaves no room to invent. A prefix chord cannot collide with zsh at all, which is why the two plugin actions sit on `prefix+alt+r` and `prefix+alt+e`.
- **Moving navigation to `alt+shift+h/j/k/l` removed the need for a passthrough allow-list entirely** — no shell, pager or TUI binds those chords, which is precisely why tmux chose them. The earlier `SMART_SPLITS_HERDR_PASSTHROUGH_RE` export is gone. It could not have worked anyway: an env var is read by the herdr SERVER once at launch (probed with `ps eww`, absent until restart), and `herdr pane process-info` reports `foreground_processes[].name` as `caffeinate`, `node` and a version string for a Claude Code pane — so no regex naming `claude` could ever match. `navigate.sh` still honours `HERDR_NAV_PASSTHROUGH_RE` for a TUI that genuinely owns the chords, but nothing needs it today.
- **`herdr integration install claude` writes `~/.claude/settings.json`, which the PRIVATE repo force-applies** (`dot_bin/executable_home:17` lists it in `PRIV_RUNTIME_OWNED`). The order is install → mirror into the private source → `home apply`; the reverse order reverts the integration on the next apply. It adds a `SessionStart` hook plus `~/.claude/hooks/herdr-agent-state.sh`, and that script's own header warns that reinstalling overwrites it. It is tracked anyway, so a fresh machine does not inherit a `settings.json` pointing at a missing file.
- **Popup commands do NOT receive `HERDR_PANE_ID`** — use `HERDR_ACTIVE_PANE_ID` for the underlying tiled pane, plus `HERDR_ACTIVE_PANE_CWD`, `HERDR_ACTIVE_TAB_ID`, `HERDR_ACTIVE_WORKSPACE_ID`, `HERDR_SOCKET_PATH` and `HERDR_BIN_PATH`. Shell-type commands run from the focused pane's working directory. A popup also inherits `FZF_DEFAULT_OPTS` from the server exactly as a tmux `display-popup` does, so every fzf inside one must restate `--height` and `--keep-right`/`--no-keep-right` — the same trap `mdr` and `switcher.sh` document.
- **`herdr pane run` echoes the command into the pane, so `wait-output --match` can match the echo instead of the output** — a marker that appears in the command string matches instantly and the wait returns in milliseconds. Pick a marker the command does not literally contain, or build it at run time (`printf "DONE%s" "_MARK"`).
- **`keys` gets its herdr rows from `herdr --default-config` merged with the deployed `config.toml`** — herdr has no `list-keys`, and `config-reference.json` is a network fetch, so those two are the only offline sources herdr reports about itself. Two parser traps, both shipped broken once: the value pattern must be `"([^"]*)"`, because a greedy `"(.*)"` swallows the trailing `# e.g. "alt"` comment that shares the line, and the section tracker must strip a leading `#` before testing for a `[…]` header, because `# [keys.indexed]` and `# [[keys.command]]` are COMMENTED in herdr's output and would otherwise leave the parser inside `[keys]`. Header detection and value matching therefore read different variables — one `#`-stripped, one not. Actions herdr omits from its own default dump (`swap_pane_*`, `copy_mode`) appear only once overridden.

## Keybind layers

Five layers, outside-in: Aerospace (WM) → Ghostty (terminal) → tmux **or herdr** (multiplexer) → zsh (shell) → neovim (editor). Each layer claims a modifier band; a layer only intercepts what it explicitly binds, everything else falls through to the next. tmux and herdr are PEERS in the same slot and never nest, so the `M-` band is free in whichever one is running.

- **Aerospace**: `ctrl-alt(-shift)` — WM-level, never reaches the terminal.
- **Ghostty**: `keybind =` in `config.ghostty` — global quick-terminal (`ctrl+grave`), scrollback/opacity, `cmd+` macOS-native combos, plus the four `ctrl+shift+` rewrites below. Minimal by design; most binds pushed down to tmux so they work over SSH too.
- **tmux**: `M-` (Alt) root table, prefix-free (`keybinds.conf`) + `copy-mode-vi` table (`copy-mode.conf`). Dual-encoding and `BTab` nuances: see Rules above. `M-f` opens the reader and therefore shadows zsh's emacs `^[f` (`forward-word`) inside every tmux pane; `Ctrl+Shift+S` (`^[^S`) is the forward-word that survives.
- **zsh**: emacs mode (`bindkey -e`) + `Ctrl` word/line editing in `.zshrc` (`W`/`E` delete-back/accept-forward, `A`/`S` jump to line start/end, `+Shift` narrows line→word); `^z` toggles into `vicmd` for one command; `^F` runs the `mdr` markdown reader.
- **herdr**: prefix `ctrl+space` (tmux parity), plus an `alt+` root band that mirrors tmux one chord for one chord (`config.toml`). Pane navigation is `alt+shift+h/j/k/l`, the same chords tmux uses, driven by `scripts/navigate.sh`. Custom commands carry a `description`, so `prefix+?` lists them by name; `alt+?` opens the cross-layer `keys` cheatsheet instead.
- **neovim**: `<leader>` (snacks pickers, `which-key.lua`), `<A-H/J/K/L>` for smart-splits pane nav under BOTH tmux and herdr — shares the M-H/J/K/L band with tmux, see below.

Nuance not covered by the Rules list: **M-H/J/K/L is shared, not layered.** tmux's root table checks `@pane-is-vim` per keypress (`if -F "#{@pane-is-vim}" "send-keys M-H" "select-pane -L"`) and forwards to neovim's own `<A-H/J/K/L>` (`smart-splits.lua`) when the active pane is vim, else runs `select-pane` itself. One binding, two consumers, arbitrated per-keypress at runtime — not a tmux-then-nvim fallthrough chain. Same pattern repeats in `copy-mode.conf`'s `copy-mode-vi` table.

## Cross-Tool Integration

- **tmux ↔ neovim**: `M-H/J/K/L` via `@pane-is-vim` (smart-splits.nvim).
- **tmux ↔ zsh**: nothing — the exit-code/status-dot wiring was removed (consumer deleted in `9b4f131`); restore recipe in `ARCHI.md` §9.
- **tmux ↔ ghostty**: terminal features (hyperlinks, clipboard, no extkeys) + `macos-option-as-alt`; `terminal-features` reset with `set -su` before appending to avoid reload duplicates.
- **herdr ↔ neovim**: `alt+shift+h/j/k/l` via `dot_config/herdr/scripts/navigate.sh`, which reads `herdr pane process-info` where tmux reads `@pane-is-vim`. Same chords, same neovim maps, different arbitrator.
- **herdr ↔ ghostty**: `[ui.toast] delivery = "terminal"` hands notifications to Ghostty. **Do not use `delivery = "system"`** — herdr then posts through `/usr/bin/osascript -e 'display notification'`, which has no bundle of its own, so macOS attributes the alert to Script Editor and clicking it activates that app. herdr knows `com.mitchellh.ghostty` and would pass it to `terminal-notifier -activate`, but that binary is not installed, so it falls back to the osascript path.
- **herdr ↔ zsh**: nothing. Navigation moved to `alt+shift+h/j/k/l` precisely so no zsh binding is shared — see Rules.

## Validation

- Ghostty: `ghostty +show-config`.
- Keybind cheatsheet: `keys --plain | awk '{print $1}' | sort -u | grep -cE '^(aerospace|ghostty|herdr|nvim|tmux|zsh)$'` — expect `6`. A bare `wc -l` also counts the two header lines. A tool dropping to zero rows means its dump broke, not that its bindings vanished.
- herdr: `herdr config check` (exit 0 and `config: ok`), then `herdr server reload-config` — the reload returns `status: applied` with a `diagnostics` array that must be empty. `home check` runs the first of these for you.
- tmux: `tmux source-file ~/.config/tmux/tmux.conf` reloads the **running** server — the point. It ADDS and OVERWRITES binds; it never removes one that left the config, so a renamed key keeps working from the old key until an explicit `tmux unbind -n <key>` or a server restart (`M-i` survived the move to `M-f` this way). **`-f` does not change the socket** (that's `-L`/`-S`), so `tmux -f /dev/null start-server … kill-server` attaches to the live socket and destroys every session (it did, 2026-08-01). Parse-check on a throwaway socket: `tmux -L cfgcheck -f /dev/null start-server \; source-file ~/.config/tmux/tmux.conf \; kill-server`.
- Dotfiles: `home check` (health) · `home sync`.
- Shell scripts: `shellcheck` (advisory — zsh unsupported, SC1071 expected).
