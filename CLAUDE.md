# Dotfiles

Managed by chezmoi. Two-repo setup: public (`~/.dotfiles`) + private (`~/.dotfiles-private`). Bootstrap: `install.sh`.

This half holds shell / tmux / ghostty / nvim / OMP and cross-tool integration. The Claude Code rig, every other agent rig, secrets, and personal tooling live in the private half — see [`~/.dotfiles-private/CLAUDE.md`](~/.dotfiles-private/CLAUDE.md). The split is by audit surface, not by importance: this repo's `.chezmoiignore` excludes `.claude` and `CLAUDE.md` so the private half is the sole source of truth for agent config.

## Rules (non-obvious, not derivable from code)

- **Source-first re-add loop** — edit chezmoi source → `home apply` → validate the runtime with the tool's own validator (see Validation) → `home re-add`. Source stays canonical; re-add captures normalization the tool applied to its own config. Never treat the runtime target as the source of truth. Operational form is injected per-edit by `~/.claude/rules/10-chezmoi.md`
- **`RUNTIME_KEYS` is empty by design** — `_capture_runtime_owned` harvests nothing live→source, because harvesting `model` fought the pinned value every apply. Consequence: a `/model` or `/config` change not mirrored into source is silently wiped on the next apply. `PRIV_RUNTIME_OWNED` force-applies two files (`~/.claude/settings.json`, `~/.pi/agent/settings.json`); mechanism in [`~/.dotfiles-private/ARCHI.md`](~/.dotfiles-private/ARCHI.md) §2.1
- **chezmoi never prunes** — deleting a source file leaves the deployed target in place. `rm` it manually after `apply`, or it becomes an unmanaged orphan nothing will ever flag
- **keybinds.conf ↔ keyb.yml must stay in sync** — always update both when changing tmux bindings
- **The workspace list lives in THREE files** — `dot_config/sketchybar/lua/items/spaces.lua`, `dot_config/sketchybar/executable_sketchybarrc` (the `left_island` bracket), and `dot_config/aerospace/aerospace.toml` (`persistent-workspaces`). Adding a workspace to fewer than all three renders and clicks but falls outside the island background, with no error. Already drifted once — `1e2658e`. Do not DRY it away; just update all three
- **tmux mouse selection is pane-aware** — drag selects within pane, copies to system clipboard via OSC 52; Shift+drag falls back to native Ghostty selection
- **tmux names Shift-Tab as `BTab`** (e.g., `M-BTab`), not `M-S-Tab`
- **Dual keybindings for Alt+Shift combos** — bind both `M-S-D` (CSI u) and `M-D` (legacy) to the same action. Ghostty 1.3.0+ (#9406) breaks `M-S-*` in modifyOtherKeys mode by stripping the Shift modifier from Option-modified keys on macOS. `extkeys` is intentionally omitted from `terminal-features` to keep Ghostty in legacy mode where case is preserved (`M-d` vs `M-D`). See keybinds.conf and tmux.conf comments for details
- **`Ctrl+R` is atuin, not fzf** — atuin initialized with `--disable-up-arrow`
- **Emacs mode default** (`bindkey -e`) with `C-z` toggle to vi — required for Alt keybinds without lag
- **Popup scripts live in `dot_config/tmux/scripts/`**, not `dot_bin/`
- **zsh config lives in `$ZDOTDIR` (`~/.config/zsh/`)** — `~/.zshenv` is a 2-line stub. Setting `ZDOTDIR` there means `$ZDOTDIR/.zshenv` is **never auto-read**; the stub sources it explicitly. Rationale + probe: `ARCHI.md` §3
- **PATH lives in `path.zsh`, called from BOTH `.zshenv` and `.zprofile`** — macOS `/etc/zprofile` runs `path_helper`, which hoists `/etc/paths` above everything and appends inherited entries to the tail. `.zprofile` is the only user file that runs after it. **Never verify a PATH change with `zsh -i -c` alone** — that's a non-login shell, so `path_helper` never fires and the breakage is invisible. Test `-l -i`, `-i`, and bare. Full story: `ARCHI.md` §3
- **`path.zsh` prepends fnm's *default alias* dir, not the per-shell multishell dir** — `~/.local/share/fnm/aliases/default/bin` is a static symlink, so it costs nothing to add (no `fnm env` spawn) and it must sit **above `$HOMEBREW_PREFIX/bin`** in the arg list. `_mrgsh_path_prepend` prepends each argument in turn, so **the LAST argument ends up FIRST** in PATH — adding an entry "after" another in the list puts it *higher*. Without this, every non-interactive zsh resolved `node` to Homebrew's (a transitive dep of `agent-browser`/`markdownlint-cli`/`supabase`, never installed on request) two majors ahead of the fnm default, and a fresh non-descendant zsh (cron, LaunchAgent, GUI) could not see `wrangler`/`cavemem`/`pnpm` at all. Interactive shells still get exact per-shell semantics because `.zshrc`'s `fnm env` prepends the multishell dir afterward. Verify with all four: `zsh -c`, `zsh -i -c`, `zsh -l -i -c`, and `env -i … zsh -c`. **`dot_bashrc` carries the same prepend and must stay in sync** — it had the identical bug (interactive bash resolved Homebrew's node; non-interactive bash escaped only because `.bashrc:10` bails out before its PATH block and `path_helper` leaves `/usr/local/bin` on top). The four root-owned `/usr/local/bin` symlinks into `fnm/aliases/default` are unmanaged machine state, not created by `install.sh`; after this change they matter only for GUI/LaunchAgent processes that read no shell rc
- **zsh startup is intentionally synchronous** — no plugin manager, no defer, no eval caching. Plugins are plain clones in `$XDG_DATA_HOME/zsh/plugins` (clone loop in `.zshrc`, update via `zsh-plugin-update`); tool inits are direct `eval "$(tool init zsh)"`. Measured median 123ms, range 121–134ms (n=15, 2026-08-01), after the `compinit` fast path was made reachable; the previously recorded 190ms never reproduced. Do not re-introduce zinit/zsh-defer/eval caches. Budget + profile: `ARCHI.md` §4
- **Static completions live in `~/.zfunc`** — generated by `update-completions` (run after upgrading gh/op/wrangler), autoloaded via compinit; never eval'd at startup
- **OMP never reaps its per-session cache files** — `.zshrc` keeps the newest 50 in a disowned background block, matched by `*.*-*-*-*-*.omp.cache` (the UUID infix is load-bearing). Two constraints, each already shipped broken once:
  - The reaper glob **must never match `init.*.zsh` or bare `omp.cache`**. `oh-my-posh init zsh` emits `precmd() { source ~/.cache/oh-my-posh/init.<hash>.zsh }` — one file, stable hash, shared by *every* live shell, and its mtime is **never refreshed**. So under any mtime-sorted keep-N it sinks to the bottom and gets reaped first, out from under running shells. Symptom is `precmd:source: no such file or directory` on every prompt in every pane, self-healing only when a new shell recreates it. Reproduce: burst >50 shells, then check the doomed slice for `init.*.zsh`. Widening the glob to "reap all shapes" caused exactly this — `40c2f4b`
  - The slice **must** be `"${(@)_c[51,-1]}"`; a plain `"${_c[51,-1]}"` joins the whole slice into one word and silently deletes nothing (this shipped broken and grew 8.5k files)
- **Ghostty `shell-integration-features` is ADDITIVE over defaults** — source sets `cursor,sudo`; effective is `cursor,sudo,title,no-ssh-env,no-ssh-terminfo,path`. The only non-default delta is `no-sudo`→`sudo`. Verify with `ghostty +show-config`, never by reading the source line. **Never set `no-path`** — it strips `/Applications/Ghostty.app/Contents/MacOS` from PATH and the `ghostty` command vanishes from the shell
- **`set -g detach-on-destroy off`** — required for park/unpark UX; keeps client attached to a remaining session when the current one is destroyed
- **Session persistence is intentionally manual** — `park-session.sh` / `unpark-session.sh` replace tmux-resurrect/continuum; no auto-restore on boot. `save-session.sh` and its `session-lib.sh` helper were deleted in `4f12a1f` (write-only, nothing read them back) — do not re-add
- **Switcher/menu use `#{session_id}` not `#{session_name}`** — tmux session names can contain apostrophes/quotes that break shell-style escaping in `display-menu` command strings; numeric `$N` IDs are quote-safe

## Cross-Tool Integration

- **tmux ↔ neovim**: `M-H/J/K/L` forwarded via `@pane-is-vim` (requires smart-splits.nvim)
- **tmux ↔ zsh**: nothing. The `@last_exit_code` / "status bar error dot" wiring was removed — the consumer was deleted by `9b4f131` and the producers were orphaned. Restore recipe (both halves required): `ARCHI.md` §9
- **tmux ↔ ghostty**: terminal features (hyperlinks, clipboard — no extkeys) + `macos-option-as-alt` for Alt binds. `terminal-features` reset with `set -su` before appending to prevent duplicates on config reload
- **zsh ↔ yazi**: `C-f` widget opens yazi; `y()` wrapper handles cd-on-exit via temp cwd file

## Validation

- Ghostty: `ghostty +show-config`
- tmux: `tmux source-file ~/.config/tmux/tmux.conf` — reloads into the **running** server, which is the point. **`-f` does NOT change the socket**, only the config file; the socket is `-L`/`-S`. So `tmux -f /dev/null start-server … kill-server` attaches to the *live* default socket and destroys every session — it killed a working session on 2026-08-01. To parse-check a config without touching the live server, always name a throwaway socket: `tmux -L cfgcheck -f /dev/null start-server \; source-file ~/.config/tmux/tmux.conf \; kill-server`
- Dotfiles health: `home check`
- Dotfiles sync: `home sync`
- Shell scripts: `shellcheck` (advisory — doesn't support zsh, SC1071 expected)
