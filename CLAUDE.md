# Dotfiles

Chezmoi, two repos split by audit surface: public (`~/.dotfiles`) + private (`~/.dotfiles-private`). Bootstrap: `install.sh`. This half is shell / tmux / ghostty / nvim / OMP and the wiring between them. Agent rigs, secrets and personal tooling live in the private half — [`~/.dotfiles-private/CLAUDE.md`](~/.dotfiles-private/CLAUDE.md). This repo's `.chezmoiignore` excludes `.claude` and `CLAUDE.md`, so the private half is the sole source of truth for agent config.

## chezmoi loop

- **RUNTIME-FIRST** — edit the deployed target, validate with the tool's own validator, then `home re-add` and commit. `~/.claude/rules/10-chezmoi.md` injects the operational form per edit and must agree with this file, or every agent enforces one policy against the other.
- **Four targets are SOURCE-ONLY.** `~/.config/glow/glow.yml` and `~/.aws/config` are templates, and `chezmoi re-add` skips a template in SILENCE — exit 0, no output, no source byte changed, `chezmoi status` still `MM`. `~/.claude/settings.json` and `~/.pi/agent/settings.json` are force-applied from source by `home`'s `_capture_runtime_owned`, so a live edit is discarded on the next private apply.
- **Deletion stays source-side in both directions.** chezmoi never prunes, so a deleted source entry leaves its target as an unflagged orphan — `rm` it by hand. The reverse is not free either: an `rm`'d target reports column-1 `D`, the drift guard blocks it, and a bare apply then prompts `has changed since chezmoi last wrote it` and, headless, exits 1 with the repo part-applied. `home apply --force` clears it.
- **`home apply` refuses up front when a target holds an uncaptured change** — `_drift_blockers` (`dot_bin/executable_home`) reads column 1 of `chezmoi status --path-style absolute`: `M` is a runtime edit, `D` a deleted target, both block. It is a PRE-FLIGHT pass over every selected repo, so one drifted private target stops the public apply too.
  - Remedy by kind: a plain file → `home re-add`. A **template** cannot be captured → edit the source, then `home apply --force`. A chezmoi **external** is the same, because `chezmoi source-path` returns a path that does not exist — a `.tmpl` test alone misses this and loops the operator through a `re-add` that can never clear it. A `PRIV_RUNTIME_OWNED` target is exempt.
  - The `home sync` hint prints only when a blocker is capturable; `cmd_sync` would otherwise claim it re-added a template while the drift stood.
  - **One hole.** chezmoi prompts before overwriting a drifted target, and off a TTY aborts that file intact — but only when it holds an `entryState` record for it. With no record the same edit shows column-1 blank, `chezmoi apply` exits 0 and destroys it silently — so `chezmoi state delete --bucket=entryState` strips protection until the next apply.
- **`RUNTIME_KEYS` is empty by design** — nothing is harvested live→source; an unmirrored `/model` or `/config` change is wiped on the next apply. Mechanism: the PRIVATE [`~/.dotfiles-private/ARCHI.md`](~/.dotfiles-private/ARCHI.md) "Deploy loop". Both repos ship an `ARCHI.md` with a deploy-loop section; every bare `ARCHI.md` below means THIS repo's.
- **`.chezmoiignore` patterns must never start with `/`** — chezmoi rejects a leading slash (`chezmoi: .chezmoiignore:6: /ARCHI.md: invalid path`) and then EVERY chezmoi command exits 1, freezing the rig. A bare `ARCHI.md` is already root-anchored; patterns match the target path relative to `~`.

## Keybinds

Five layers, outside-in: Aerospace (`ctrl-alt(-shift)`, never reaches the terminal) → Ghostty (`keybind =` in `config.ghostty`; minimal by design, most binds pushed down to tmux so they work over SSH) → tmux (`M-` root table in `keybinds.conf`, plus `copy-mode-vi`) → zsh (emacs mode; `^z` toggles `vicmd` for one command, `^F` opens `mdr`) → neovim (`<leader>` pickers, `<A-H/J/K/L>`). A layer only intercepts what it explicitly binds; everything else falls through.

- **Descriptions live as tmux `-N` notes, never in a second file** — `dot_bin/executable_keys` generates the whole cheatsheet at run time from each tool's own reporting (`aerospace config --get`, `ghostty +list-keybinds`, `tmux list-keys -N`, `zsh -i -c bindkey`, `nvim --headless` + `nvim_get_keymap`). A binding worth remembering gets `-N "Label"` on its own `bind` line. A hand-maintained copy drifted repeatedly and is deleted; do not reintroduce one. Two parser quirks: `list-keys -N` prints the prefix key ahead of EVERY row including the prefix-free root table, and keys appear both double-quoted (`"M-;"`) and backslash-escaped (`\#`) in the same table.
- **Before binding a root `M-<key>`, check all three layers.** `M-b` and `M-f` are NOT free: Ghostty ships `alt+arrow_left=esc:b` and `alt+arrow_right=esc:f`, so the arrows arrive as those, yet tmux lists both as unbound. zsh owns most of the rest — probe `zsh -i -c bindkey`, because a root-table bind intercepts before the pane.
- **Dual bindings for Alt+Shift** — bind both `M-S-D` (CSI u) and `M-D` (legacy). Ghostty (#9406) strips Shift from Option-modified keys in modifyOtherKeys mode; `extkeys` is deliberately omitted from `terminal-features` to stay in legacy mode, where case survives.
- **tmux names Shift-Tab `BTab`** (`M-BTab`, not `M-S-Tab`).
- **`M-H/J/K/L` is shared, not layered** — tmux's root table checks `@pane-is-vim` per keypress and either forwards to neovim or runs `select-pane` itself. One binding, two consumers, arbitrated at runtime, not a fallthrough chain. `copy-mode.conf` repeats the pattern.
- **`smart-splits.nvim` is what SETS `@pane-is-vim`**; nothing under `dot_config/tmux/` sets it, everything there only reads it. Drop the plugin and both break silently but differently: `M-H/J/K/L` falls through to `select-pane`, while `Ctrl+Shift+W/E/A/S` sends the vim pane a sequence nvim does not bind.
- **zsh's `Ctrl+Shift+W/E/A/S` are Ghostty rewrites arbitrated by tmux, not zsh keys** — legacy encoding cannot distinguish `Ctrl+Shift+X` from `Ctrl+X`, so `config.ghostty` maps each to `text:\x1b\x<byte>`; tmux receives `M-C-x` and splits it on `@pane-is-vim`, giving vim panes plain `Ctrl+X` back and every other pane `M-C-x`, which `.zshrc` binds as `^[^X`. **Mode-scoped, not blanket protection** — it saves insert mode; normal mode behaves the same either way. Three accepted holes: `Ctrl+Shift+A` still increments in neovim normal mode; outside tmux there is no arbitration; `beginning-of-line`/`end-of-line` exist only under Ghostty, since `^A`/`^E` are reassigned and Home/End are unbound.
- **Forward zsh motions bind the `.`-prefixed builtin widgets** — `'^S' .end-of-line`, `'^[^S' .forward-word`. zsh-autosuggestions lists `.*` in `ignore_widgets`, so the dot form moves the cursor without swallowing the suggestion; the undotted names are in its ACCEPT lists and are used deliberately on `Ctrl+E` / `Ctrl+Shift+E`. Backward motions need no guard — nothing accepts leftwards.
- **`Ctrl+R` is atuin, not fzf** (`--disable-up-arrow`). **Emacs mode is the default**, required for lag-free Alt binds.

## tmux pop-ups

- **Pop-up scripts live in `dot_config/tmux/scripts/`**, not `dot_bin/`. `keys` and `mdr` are the exceptions precisely because they must run standalone outside tmux; the `M-?` pop-up is only a wrapper around `keys`, never a second implementation, and draws no frame of its own (`-b none`) because `keys` draws one.
- **One shared layout across every fzf pop-up.** `--border-label` is a plain title (` Reader `, ` Switcher `) with NO `--border-label-pos`, so it centres on fzf's default and matches every `display-popup -T '#[align=centre] …'`. Tab bar is `--header` with `--header-first --header-border=line`; action hints are `--footer` with `--footer-border=line`.
- **Key hints are vim notation, never `Ctrl+X`** — `<CR>`, `<C-e>`, `<C-/>`, `<Esc>`, lowercase — in the header and footer of `reader.sh`, `switcher.sh` and `keys`. Prose about zsh or Ghostty keys keeps the `Ctrl+Shift+X` register, which is what those layers call them.
- **`display-popup` inherits `FZF_DEFAULT_OPTS` from the tmux server environment, so every fzf inside one must STATE the options it depends on.** An inherited option is invisible at the call site. `--height=60%` is the loud one: fzf draws in the top 60% with dead space below. Command-line options win.
- **`--keep-right` truncates `--header` and `--footer` from the LEFT**, and both span the LIST column, itself a fraction of a pop-up that is a fraction of the terminal. The reader states `--keep-right` because its path rows need it, and therefore lists its primary action LAST; the switcher states `--no-keep-right` and lists its primary action FIRST. Each ordering is correct for its own truncation direction. `--no-keep-right` is absent from `fzf --help` but accepted. Measure at the pop-up's real interior width, never in a bare pane — `capture-pane` cannot photograph an `fzf --tmux` pop-up, but a plain pty at its column count can.
- **The pop-up surface is painted crust on purpose.** `popup-style` sets `bg=#{@clr_crust}` so a `display-popup` matches every fzf pop-up and every menu. The hue was never the difference — Ghostty's own background IS crust. Opacity was: an unpainted cell shows `background-opacity` and `background-blur`, a painted one is opaque. This trades the glass on the Scratch, Lazygit, reader-render and `prompt.sh` pop-ups for one surface.
- **Menu colours are OPTIONS, not per-command arguments.** `menu-style`, `menu-selected-style` and `menu-border-style` in `theme.conf` are format-expanded and theme every menu on the server at once; `display-menu -s/-S/-H` takes a literal colour only, so no call site carries a copy.
- **Switcher and menus use `#{session_id}`, not `#{session_name}`** — names can carry quotes that break `display-menu` escaping; numeric `$N` IDs are quote-safe.
- **The switcher's bookmark store is runtime state at `~/.local/state/switcher/bookmarks`; chezmoi must NEVER manage that path** — the UI writes it, so a managed copy is overwritten on the next `home apply`. One absolute path per line, so the toggle is `grep -vxF` and needs no `jq`. The declarative half (`~/.config/switcher/projects.json`) is separate and optional; its `baseFolders[].scope` is read and discarded, so a value there does nothing.
  - **`Ctrl+S` is not free in the rig at large** — `.zshrc` binds `^S` to `.end-of-line` — but fzf owns the key inside its own pop-up, so there is no conflict to fix.
  - **`Ctrl+S` binds `transform(...)`, never `execute-silent(...)+reload(...)`** — the chained form reloads unconditionally, and a Grep row is always a no-op, so one keypress rebuilt the whole list for nothing. Under `transform` the script emits a `reload(...)` only when it actually wrote.
  - **That reload must replay the ACTIVE tab, not `all`** — `do_source` records the tab into `$SWITCHER_TAB_FILE`; `--source-current` reads it back.
  - **`is_bookmarked` must guard `-n "$1"`** — with no store on disk the set is two bare newlines, so an unguarded match returns true for an empty path, and the tmux rows are the one source never filtered by `-d`.
  - Every `fd` call site strips a trailing `/`, and so do the bookmark and `favorites` loops: `fd` appends one, the store holds the stripped form, and the merge deduplicates on the literal string.
- **The switcher's search scope is `--nth '1,3..'`** — name column plus everything from the path column on. `--nth` applies AFTER `--with-nth` transformation. Name-only missed a path query entirely, because the All view deduplicates by path and keeps the tmux session's name for the row.

## The reader (`mdr` + `reader.sh`)

- **TWO fzf call sites that must stay in sync.** `M-i` runs `reader.sh`, which drives `~/.bin/mdr` through `--source`, `--preview`, `--copy`, `--copy-path`, `--edit` and `--visual`; `mdr` carries its own fzf for the standalone `Ctrl+F` path. The six action binds and the footer string are byte-duplicated across the two files with NO shared source, so an action added to one and not the other advertises a key that does nothing. Four tabs — All (`<C-a>`, default), Docs (`<C-d>`), Scratch (`<C-s>`), Files (`<C-f>`) — reload the list in place. The tab bar is deliberately NOT duplicated: `mdr` takes its view as a CLI flag (`mdr --docs`), so the pop-up passes none and starts on All. The bare word does not work — `mdr docs` treats `docs` as the directory and exits 1, and a flag plus a directory is two positional arguments and exits 2.
- **Row rendering is `perl`, never a bash `while read` loop** — the loop was an order of magnitude slower on the large Files view. Rows are NUL-delimited `<display><TAB><path>` with the path **last**, and every tab and newline in the display half is replaced, so the first tab is always the separator the preview and pager cut on. The display is the full relative path, never a padded name column: fzf matches the `--with-nth` text only, so padding silently breaks path-ordered queries.
- **A positive `--glob` is a WHITELIST, so a view that lists non-markdown must carry no markdown glob at all** — `--glob '.scratchpad'` alone returned zero rows for Files, because the directory matched and nothing inside it did. Files runs the bare walk instead.
- **`.scratchpad` is re-included with a bare `--glob '.scratchpad'`, not a second `--no-ignore` pass** — the ignore file ignores the DIRECTORY, so rg prunes it before descending and no markdown glob reaches inside. A whitelist glob on the directory name stops the prune; files below are then judged on their own paths. `--glob '.scratchpad/**'` does NOT work, because it never matches the directory entry.
- **The Scratch tab walks its roots with `--no-ignore`** — the global gitignore excludes both `.claude` and `.scratchpad` outright, so dropping the flag silently empties the tab.
- **`.claude` is excluded by an explicit `--glob '!.claude'`, never by gitignore** — off-repo it is precisely `~/.claude` that would swamp the list. The Scratch tab is where it is read. Inside a repo the ignore file only prunes directories, which is why a positive glob still lists `CLAUDE.md` and `AGENTS.md`.
- **The walk is capped only off-repo, and the gate reads the CURRENT DIRECTORY.** rg applies ignore rules only inside a repository, so off-repo all of `$HOME` is fair game and uncapped it emits tens of thousands of rows on one keypress. `git rev-parse --is-inside-work-tree` gates `--max-depth 6` plus `/`-anchored excludes. Because the gate reads the cwd, the walk must BE the cwd: `mdr` takes at most one directory and `cd`s into it. Passing a path while the shell sat in a repo skipped the cap, and the anchored excludes go inert against an explicit path argument. **The cap loses files and says nothing** — off-repo, anything deeper than 6 components is unreachable.
- **Renderer flags are restated on purpose.** `~/.config/bat/config` is tuned for non-interactive use, so the reader passes its own paging, style and pager (`less -R`, since delta decorates diffs, not plain files). Both tools drop colour when stdout is not a tty, which is exactly an fzf preview pane, so previews force `--color=always` / `-s <style>`.
- **`glow` renders plain text off a tty EVEN with `style:` set in `glow.yml`** — that key works on a tty only, so the `-s` flag is what colours the preview.
- The Catppuccin palette and the fzf colour string are copied into `mdr` rather than sourced from `scripts/colors.sh`: the reader must run with no tmux on disk.
- **The selection temp file is removed explicitly, not by the EXIT trap** — the terminal path is `exec glow`, which never runs the trap, so the bare `rm` that looks redundant is load-bearing.
- **`Ctrl+F` took `forward-char`**, which zsh-autosuggestions lists in `ZSH_AUTOSUGGEST_ACCEPT_WIDGETS`, so the bind removes one way to accept a whole suggestion. `Ctrl+E` is in the same list and still does it.

## tmux behaviour

- **Mouse selection is pane-aware** — drag copies via OSC 52; Shift+drag falls back to native Ghostty selection.
- **`set -g detach-on-destroy off`** — park/unpark UX; the client stays attached when the current session dies.
- **Session persistence is intentionally manual** — `park-session.sh` / `unpark-session.sh`, no auto-restore. An earlier write-only save/restore pair was deleted; do not re-add it.
- **`tmux source-file` reloads the RUNNING server, which is the point** — it ADDS and OVERWRITES binds but never removes one that left the config, so a renamed key keeps working from its old key until an explicit `unbind` or a server restart.
- **`-f` does not change the socket** (that is `-L`/`-S`), so `tmux -f /dev/null start-server … kill-server` attaches to the LIVE socket and destroys every session. Always parse-check on a named throwaway socket.

## glow

- **`dot_config/glow/glow.yml` is a chezmoi template for one reason** — glow does not expand `~` in its `style:` key, so the Catppuccin Mocha style needs `{{ .chezmoi.homeDir }}`. The two failure modes differ and only one is loud: an unexpanded `~` degrades quietly to unstyled output (exit 0), while an ABSOLUTE path that does not exist kills every glow call on the machine with `Error: specified style does not exist`, exit 1, no output. `mdr` falls back to the built-in `dark` when the file is unreadable.
- `mocha.json` is a glamour `StyleConfig`. Its `chroma` block stays hand-written: glamour has no `code_block.theme` escape hatch and drops unknown `StyleConfig` keys in silence, so a `"theme"` key renders byte-identical to no theme at all. Chroma quantises to the xterm-256 cube, so code-block colours are near, not exact. glow ships no catppuccin built-in.

## zsh

- **Config lives in `$ZDOTDIR` (`~/.config/zsh/`)** — `~/.zshenv` is a stub; with `ZDOTDIR` set there, `$ZDOTDIR/.zshenv` is never auto-read, so the stub sources it explicitly. Probe: `ARCHI.md` §3.
- **PATH lives in `path.zsh`, called from BOTH `.zshenv` and `.zprofile`** — macOS `path_helper` (via `/etc/zprofile`) hoists `/etc/paths`, and only `.zprofile` runs after it. **Never verify PATH with `zsh -i -c` alone** — non-login, so `path_helper` never fires. Test `-l -i`, `-i`, bare, and `env -i`.
- **`path.zsh` prepends fnm's DEFAULT ALIAS dir** (`~/.local/share/fnm/aliases/default/bin` — a static symlink, no `fnm env` spawn) and it must sit ABOVE `$HOMEBREW_PREFIX/bin`. `_mrgsh_path_prepend` prepends each argument in turn, so the LAST argument lands FIRST. Without this, non-interactive zsh resolves Homebrew's node and fresh non-descendant shells (cron, LaunchAgent, GUI) lose their node tooling. **`dot_bashrc` carries the same prepend and must stay in sync.** The root-owned `/usr/local/bin` symlinks into the fnm alias dir are unmanaged machine state, not created by `install.sh`; they matter only for GUI and LaunchAgent processes that read no rc.
- **Startup is intentionally synchronous** — no plugin manager, no defer, no eval caching; plain clones in `$XDG_DATA_HOME/zsh/plugins` (update: `zsh-plugin-update`), direct `eval "$(tool init zsh)"`. Do not reintroduce zinit, zsh-defer or eval caches. Budget and profile: `ARCHI.md` §4.
- **Static completions live in `~/.zfunc`** — generated by `update-completions`, never eval'd at startup. Run it after upgrading gh, op or wrangler.
- **`DIRENV_LOG_FORMAT=""` silences direnv's status lines but KEEPS its errors** — set in `.zshrc` above the hook. It must be exported, since the direnv binary reads it on each hook run. A blocked or failing `.envrc` still prints, because errors do not use that format.
- **OMP never reaps its per-session cache files** — `.zshrc` keeps the newest 50, glob `*.*-*-*-*-*.omp.cache` (the UUID infix is load-bearing). Two constraints, each shipped broken once:
  - The glob **must never match `init.*.zsh` or bare `omp.cache`** — `init.<hash>.zsh` is one stable-named file shared by every live shell, with an mtime that never refreshes, so any mtime-sorted keep-N reaps it first. Symptom: `precmd:source: no such file or directory` on every prompt in every pane.
  - The slice **must** be `"${(@)_c[51,-1]}"` — the unparenthesised form joins to one word and deletes nothing.

## Ghostty

- **`shell-integration-features` is ADDITIVE over defaults** — verify the effective value with `ghostty +show-config`, never the source line.
- **Never set `no-path`** — it strips Ghostty's app dir from PATH and the `ghostty` command vanishes.

## neovim

- **LazyVim plus a thin override layer** — `lua/config/*.lua` carries only deltas from LazyVim's defaults, `lua/plugins/` only what LazyVim does not ship. Check LazyVim's own config before adding an override; it already sets most of it. Delta table: `dot_config/nvim/README.md`.
- **The colorscheme is `catppuccin-mocha`, never bare `catppuccin`** — Neovim ships `$VIMRUNTIME/colors/catppuccin.vim`, and the bare name resolves to that builtin, which ignores the plugin's `opts`; `transparent_background` then silently does nothing. Probe with `verbose highlight Normal` — it names the file that last set it.
- **lazy.nvim's update checker is off by preference** — no background fetches, no nags. The checker never writes `lazy-lock.json`; only install, update and clean do. The lock is chezmoi-tracked, so update deliberately: `:Lazy update` then `home re-add`. **Never `:Lazy sync`**, which uninstalls anything absent from the current spec.

## Aerospace and sketchybar

- **The workspace list lives in THREE files** — `dot_config/sketchybar/lua/items/spaces.lua`, `dot_config/sketchybar/executable_sketchybarrc` (the `left_island` bracket), and `dot_config/aerospace/aerospace.toml` (`persistent-workspaces`). Fewer than all three renders but falls outside the island, with no error. Do not DRY it away; update all three.
- **A window with no rule falls to the catch-all and floats on whichever workspace has focus** when it opens. That is deliberate.
- **An AeroSpace rule script MUST call `aerospace` by absolute path.** AeroSpace.app runs with `PATH=/usr/bin:/bin:/usr/sbin:/sbin`, so a bare `aerospace` is `command not found` in every rule-triggered run, and a script's own `2> /dev/null` turns that into a silent no-op — the action simply never happens and nothing reports it.
- **WS4's 2/3 : 1/3 split is a script, because AeroSpace resizes in PIXELS only**, so a ratio has to be computed. `dot_config/aerospace/scripts/executable_ws4-split.sh` reads the three gap values out of `aerospace config` rather than hardcoding them, and retries the window lookup, because a window AeroSpace has just detected may not be in its model yet, and refuses to run at all unless WS4 holds exactly two windows. Width comes from `NSScreen.visibleFrame` keyed by AeroSpace's own monitor id — **not** Finder's `bounds of window of desktop`, which returns the full frame (a side Dock then overstates the usable width) and needs a separate Automation→Finder TCC grant. The rule-triggered path is `unverified`; the script has only been observed run by hand.

## Cross-tool integration

- **tmux ↔ neovim**: `M-H/J/K/L` via `@pane-is-vim` (smart-splits.nvim).
- **tmux ↔ zsh**: nothing. The exit-code/status-dot wiring was removed; restore recipe in `ARCHI.md` §9.
- **tmux ↔ ghostty**: terminal features (hyperlinks, clipboard, no extkeys) plus `macos-option-as-alt`. `terminal-features` is reset with `set -su` before appending, to avoid duplicates on reload.

## Validation

- Ghostty: `ghostty +show-config`.
- tmux, parse-check on a throwaway socket: `tmux -L cfgcheck -f /dev/null start-server \; source-file ~/.config/tmux/tmux.conf \; kill-server`.
- Keybind cheatsheet: `keys --plain | awk '{print $1}' | sort -u | grep -cE '^(aerospace|ghostty|nvim|tmux|zsh)$'` — expect `5`. A bare `wc -l` also counts the two header lines. A tool dropping to zero rows means its dump broke, not that its bindings vanished.
- Dotfiles: `home check` · `home sync`.
- Shell scripts: `shellcheck` (advisory — zsh unsupported, SC1071 expected).
